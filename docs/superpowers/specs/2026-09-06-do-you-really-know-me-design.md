# 「你真的懂我吗」MVP 设计文档

日期：2026-09-06  
状态：已由用户确认，待实施计划  
目标域名：`me.ly0688.online`

## 1. 产品概述

「你真的懂我吗」是一款轻量、适合社交分享的网页产品。创建者先回答固定的 25 道有趣问题，再把测试链接分享给朋友；朋友猜测创建者会选择什么，系统计算双方答案的一致程度，并用轻松、不攻击人的文案呈现结果。

产品核心不是传统心理测试，也不输出人格类型，而是制造一个明确的社交问题：

> 朋友眼里的你，和真正的你，到底差多少？

MVP 唯一目标是验证三件事：用户是否愿意创建测试、是否愿意分享、朋友完成后是否愿意继续创建自己的测试。

## 2. 目标与非目标

### 2.1 MVP 目标

- 创建者无需注册即可完成 25 题并生成测试。
- 生成互相隔离的公开分享链接和私密管理链接。
- 朋友无需注册即可完成挑战并得到 0～100% 的默契度。
- 结果页显示关系文案、1～3 道“最离谱错题”和强裂变入口。
- 创建者可查看挑战人数、平均分和排行榜。
- 刷新或短暂断网不会轻易丢失未提交进度。
- 手机端优先，兼容微信、QQ 等内置浏览器。
- 记录创建、分享、挑战和裂变所需的核心漏斗事件。

### 2.2 MVP 明确不做

- 好友系统、关注、私信、评论区或社区排行榜。
- 复杂账号体系、会员、付费、广告。
- AI 聊天、AI 人格分析或复杂心理学算法。
- 情侣模式、宿舍模式等衍生题库。
- 完整答案公开、全站搜索或公开测试广场。

## 3. 已确认的产品决策

- 正式名称：**你真的懂我吗**。
- 视觉方向：**朋友手帐**——轻松、有梗、适合传播，但保持干净，不幼稚。
- 技术路线：新建独立的 Next.js + TypeScript + Tailwind CSS + Supabase 项目，部署到 Vercel。
- 新站域名：`me.ly0688.online`。
- 原提问箱继续使用 `ly0688.online` 与 `www.ly0688.online`，不改旧站代码和数据。
- 第一版不注册；管理能力依赖一次性展示的私密管理链接。
- 朋友完成后只揭示 1～3 道错题，不展示完整正确答案。
- 使用完全一致计分：每题一致得 4 分，25 题共 100 分。
- 固定使用需求中给出的 25 道题，不改变题目和选项。

## 4. 用户流程与页面

### 4.1 创建者路径

1. 访问首页 `/`。
2. 点击“创建我的测试”，进入 `/create`。
3. 填写昵称，开始 25 道题。
4. 每页只显示一道题；选择后提供明确反馈并进入下一题。
5. 答完后向服务端提交昵称和 25 个答案。
6. 服务端创建测试并返回：
   - 公开分享地址：`/t/{shareCode}`
   - 私密管理地址：`/m/{manageToken}`
7. 完成页以“档案封存”的轻量仪式感展示两个链接，并强提醒复制或保存管理链接。

### 4.2 朋友路径

1. 打开 `/t/{shareCode}`，看到“你有多了解 {创建者昵称}？”。
2. 填写自己的昵称并开始挑战。
3. 回答相同的 25 道题，页面持续显示“你正在猜：{创建者昵称}”。
4. 服务端计算得分并写入挑战记录。
5. 跳转结果页 `/r/{attemptId}`，显示：
   - 默契度大数字；
   - 固定分数区间文案；
   - 1～3 道最离谱错题；
   - “我也要创建自己的测试”按钮。

### 4.3 创建者管理路径

1. 打开私密管理地址。
2. 服务端验证管理令牌，并将管理权限换成仅当前站点可用的 HttpOnly Cookie。
3. 随即重定向到不含原始令牌的管理页，减少令牌出现在地址栏、截图和日志中的时间。
4. 页面显示挑战人数、平均了解度和排行榜。
5. 页面可再次复制公开测试链接。

管理链接丢失后，MVP 不提供账号或人工恢复机制。完成页必须明确告知用户这一限制。

## 5. 视觉与交互设计

### 5.1 视觉语言

- 奶油色背景、墨黑描边、珊瑚橙主按钮、紫色辅助、黄色重点标记。
- 中文正文采用清晰的现代黑体；分数、题号和档案编号使用等宽字体。
- 使用少量手写标记、贴纸和轻微错位阴影，营造“朋友手帐”感。
- 不使用 MBTI、人格雷达图、心理测评术语或企业 SaaS 布局。
- 不沿用旧提问箱的重度赛博朋克视觉。

### 5.2 关键页面

首页第一屏仅保留：

- 品牌名“你真的懂我吗”；
- 标题“你朋友真的懂你吗？”；
- 两句玩法说明；
- “创建我的测试”主按钮；
- “25 个问题 / 约 3 分钟 / 无需注册”三个轻量标签。

答题页包含：

- `08 / 25` 形式的数字进度和细进度条；
- 大字号问题；
- 四个整块可点击选项；
- 创建者或正在猜测的对象提示；
- 本地保存状态提示。

结果页包含：

- 默契度大数字；
- 对应区间的固定关系文案；
- 1～3 张错题对比卡；
- 明显的“我也要创建自己的测试”按钮；
- 可生成或保存的 3:4 竖版分享卡。

### 5.3 动效与可访问性

- 选择按压、卡片滑入和分数递增动画控制在约 180～240ms。
- 尊重系统 `prefers-reduced-motion`，减少动态效果时禁用非必要动画。
- 选项点击区域满足手机单手操作；状态不能只依赖颜色表达。
- 页面不使用频繁弹窗；重要错误就地显示。

## 6. 技术架构

### 6.1 应用栈

- Next.js App Router
- React
- TypeScript 严格模式
- Tailwind CSS
- Supabase PostgreSQL
- Vercel 部署

浏览器负责渲染和未提交草稿；所有核心数据写入、管理令牌校验、答案比对和计分都由 Next.js 服务端完成。Supabase 的服务密钥仅存在于 Vercel 服务端环境变量中，不能出现在客户端包里。

### 6.2 组件边界

- `QuestionCard`：显示单题和四个选项，不关心持久化。
- `QuizProgress`：显示题号和进度。
- `QuizSession`：管理当前题号、答案、前后导航和本地草稿。
- `ResultScore`：展示分数与关系文案。
- `MismatchCard`：展示单道错题对比。
- `ShareActions`：复制链接、调用系统分享和生成分享卡。
- `Leaderboard`：显示人数、平均分和排行榜。
- 服务端领域函数：创建测试、创建挑战、计分、挑选错题、管理令牌交换、事件记录。

各单元通过明确的类型接口通信；页面只组合组件，避免把业务逻辑堆进单个路由文件。

## 7. 数据模型

### 7.1 `question_sets`

- `id` UUID，主键
- `version` INTEGER，唯一
- `is_active` BOOLEAN
- `created_at` TIMESTAMPTZ

### 7.2 `questions`

- `id` UUID，主键
- `question_set_id` UUID，外键
- `sort_order` SMALLINT
- `prompt` TEXT
- `options` JSONB，固定四项并保留 A/B/C/D 顺序
- `category` TEXT，仅内部使用，不在答题 UI 显示
- `mismatch_priority` SMALLINT，用于优先挑选有传播价值的错题

约束：同一题集内 `sort_order` 唯一；激活题集必须正好包含 25 题。

### 7.3 `tests`

- `id` UUID，主键
- `question_set_id` UUID，外键
- `nickname` VARCHAR(20)
- `share_code` VARCHAR，唯一随机短码
- `manage_token_hash` TEXT，只保存高强度随机令牌的哈希
- `created_at` TIMESTAMPTZ

### 7.4 `creator_answers`

- `test_id` UUID，外键
- `question_id` UUID，外键
- `answer` CHAR(1)，限定 A/B/C/D

联合主键：`test_id + question_id`。

### 7.5 `attempts`

- `id` UUID，主键
- `test_id` UUID，外键
- `nickname` VARCHAR(20)
- `score` SMALLINT，限定 0～100 且为 4 的倍数
- `idempotency_key` UUID，用于避免重复提交
- `created_at` TIMESTAMPTZ

### 7.6 `attempt_answers`

- `attempt_id` UUID，外键
- `question_id` UUID，外键
- `answer` CHAR(1)
- `is_correct` BOOLEAN

联合主键：`attempt_id + question_id`。

### 7.7 `analytics_events`

- `id` BIGINT，主键
- `event_name` TEXT
- `anonymous_session_id` UUID
- `test_id` UUID，可空
- `attempt_id` UUID，可空
- `metadata` JSONB，仅保存非敏感上下文
- `created_at` TIMESTAMPTZ

分析事件不得把题目答案、管理令牌或原始 IP 写入 `metadata`。

## 8. 服务端接口与数据流

建议使用 Route Handlers；接口名可在实施计划中微调，但职责必须保持独立。

- `POST /api/tests`：验证昵称和完整 25 题答案，创建测试，返回分享地址与仅展示一次的管理地址。
- `GET /api/tests/{shareCode}`：只返回创建者昵称、题集和开始挑战需要的公开信息，绝不返回创建者答案。
- `POST /api/tests/{shareCode}/attempts`：验证朋友答案，服务端比对、计分、写入挑战，并返回结果 ID。
- `GET /api/results/{attemptId}`：返回分数、区间文案和 1～3 道错题；不返回完整答案表。
- `GET /api/manage/exchange/{manageToken}`：校验令牌哈希、建立 HttpOnly 管理会话并重定向。
- `GET /api/manage/tests/{testId}`：验证管理会话后返回排行榜与统计。
- `POST /api/events`：接收白名单内的分析事件。

写入接口使用 Zod 或等价方案做服务端结构校验。朋友挑战提交必须包含幂等键；同一幂等键重复请求返回同一挑战结果。

## 9. 计分与结果规则

### 9.1 分数

每道答案与创建者完全一致得 4 分：

`score = correctAnswerCount × 4`

### 9.2 固定关系文案

- 90～100：离谱，你是真的懂 TA。
- 80～89：基本属于 TA 一个眼神你就知道什么意思。
- 70～79：很熟，但还是藏了一些你不知道的东西。
- 60～69：认识不少，但你对 TA 的理解有点停留在表面。
- 40～59：你认识的是 TA，还是你想象中的 TA？
- 0～39：建议重新认识一下。

### 9.3 错题挑选

从答错题中按 `mismatch_priority` 优先，再使用稳定随机顺序选择最多 3 题。稳定随机种子使用挑战 ID，保证同一次结果刷新后内容不跳变。

若答错 1～2 题，则全部显示；若满分，则显示单独的满分彩蛋，不强行制造错题。

点评使用预设模板，不调用 AI，不声称心理学结论。

## 10. 本地状态与恢复

- 创建者草稿以题集版本为键保存到 localStorage。
- 朋友草稿以 `shareCode` 为键保存，避免多个测试互相覆盖。
- 草稿包含昵称、已选答案、当前题号和更新时间，不包含管理令牌。
- 提交成功后清除对应草稿。
- 检测到有效草稿时，允许用户继续或重新开始；不使用阻塞式浏览器弹窗。

## 11. 安全与隐私

- `shareCode` 使用不可连续枚举的随机短码。
- 管理令牌至少使用 32 字节安全随机值；数据库只保存哈希。
- 管理令牌交换成功后写入 `Secure`、`HttpOnly`、`SameSite=Lax` Cookie，并从 URL 移除原令牌。
- 创建者答案不得在挑战提交前发送到客户端。
- 分数、`is_correct` 和错题均由服务端计算。
- Supabase 核心表默认拒绝匿名客户端直接访问；应用服务器执行最小权限数据操作。
- 对昵称、路由参数、答案数量与选项值做严格校验。
- React 默认转义用户昵称；禁止使用未清洗的 `dangerouslySetInnerHTML`。
- 对创建测试、提交挑战和事件写入实施速率限制、蜜罐字段及合理请求体上限。
- 对外错误不包含 SQL、堆栈、环境变量名或内部 ID。

## 12. 异常处理

- 网络错误：保留草稿，显示非阻塞重试按钮。
- 重复提交：依靠幂等键返回原结果，不产生重复排行榜记录。
- 无效分享码：显示友好空状态和创建自己测试的入口。
- 无效管理令牌：统一显示无权限，不确认测试是否存在。
- 数据库暂时不可用：展示稍后重试，不清除本地答案。
- 题集版本异常或题数不为 25：服务端拒绝创建测试并记录内部错误。
- 分享 API 不可用：回退为复制链接。
- 分享卡生成失败：不影响查看结果和复制普通链接。

## 14. 测试策略

### 14.1 单元测试

- 25 题计分及 0、边界区间、满分。
- 分数到关系文案的映射。
- 错题优先级、稳定随机和不足 3 题的情况。
- 昵称、答案、分享码和管理令牌输入校验。
- 管理令牌哈希验证和幂等键处理。

### 14.2 集成测试

- 创建测试后仅返回一次管理令牌。
- 公开测试接口不泄露创建者答案。
- 挑战提交正确计分并写入排行榜。
- 相同幂等键不会重复创建挑战。
- 管理会话不能读取其他测试的数据。
- 无权限请求无法读取排行榜。

### 14.3 端到端测试

至少完整验证：

1. 手机尺寸打开首页并开始创建。
2. 答题中途刷新后继续。
3. 完成 25 题并获得两条链接。
4. 使用公开链接以朋友身份完成挑战。
5. 结果分数、文案和错题正确。
6. 点击裂变入口创建新测试。
7. 使用管理链接看到更新后的挑战人数、平均分和排行榜。

同时覆盖微信内置浏览器常见视口、Safari、Chrome 和桌面端基本可用性，并验证 `prefers-reduced-motion`。

## 15. 部署与域名

新站使用独立 GitHub 仓库、独立 Vercel 项目和独立 Supabase 项目。

上线顺序：

1. 在 Vercel 预览地址完成数据库迁移和完整验收。
2. 在当前域名 DNS 中新增 `me` 子域名记录。
3. 将 `me.ly0688.online` 绑定到新 Vercel 项目。
4. 验证 HTTPS、分享链接、管理 Cookie 和真实手机答题。
5. 保持 `ly0688.online` 与 `www.ly0688.online` 继续指向旧提问箱。

此次上线不搬迁、不覆盖、不删除旧提问箱的项目、域名绑定或数据库。

## 16. MVP 验收标准

- 用户能在手机上无需注册完成创建、分享、挑战、看结果和看排行榜的闭环。
- 创建者与朋友的 25 道题均与需求原文完全一致，顺序与选项不变。
- 计分始终为一致题数乘 4，排行榜统计正确。
- 朋友提交前无法通过公开页面或接口获得创建者答案。
- 结果页只展示最多 3 道错题；满分有专属结果。
- 刷新不会轻易丢失未提交进度，失败提交可重试且不重复记分。
- 八个指定埋点可用于还原核心漏斗。
- `me.ly0688.online` 正常使用 HTTPS；原提问箱域名保持正常。
- 首发版本没有主动加入非 MVP 功能。
