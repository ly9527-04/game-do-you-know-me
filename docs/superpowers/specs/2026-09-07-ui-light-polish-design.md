# 「你真的懂我吗」全站轻量 UI 精修设计

## 目标

在不改变题目、流程、数据结构、权限和 URL 的前提下，将当前偏粗硬的手帐界面调整为更轻盈、圆润、适合朋友分享的社交卡片风格。新版应让首次访问者立即理解玩法，让 25 题连续作答保持舒适，并让结果页更适合截图传播。

## 范围

本轮覆盖首页、创建昵称页、创建者答题页、朋友入口与答题页、创建完成页、结果页、排行榜，以及加载、错误、草稿恢复等公共状态。数据库迁移、题库内容、计分规则、接口契约、管理鉴权、埋点事件名和域名配置均不调整。

## 视觉方向

采用“轻盈社交卡片”为主方向，并只在结果页的大分数区域借用少量“夜色实验室”的强对比。整体气质是轻、圆、清楚；视觉记忆点集中在首页标题与结果分数，其余页面保持安静。

### B 方案还原基准

本轮以最初确认的“B · 轻盈社交卡片”示意图为视觉基准，而不是只套用其色板。以下元素属于方向本身，不可再次省略为普通文字和表单：

- 首页右上方的淡紫色圆形视觉锚点。
- 主标题主动换行为“你真的 / 懂我吗？”，形成紧凑的两行标题块。
- 主按钮下方使用珊瑚、黄色、淡紫三张圆角信息卡，而非三枚白色描边胶囊。
- 主要内容形成清楚的卡片组合与前后层次，不以大面积空白代替构图。
- 桌面端保持移动产品的紧凑尺度，主按钮不得机械铺满 42rem 内容宽度。
- 创建入口、朋友入口、答题、完成、结果和排行榜沿用同一套“浅色卡片 + 彩色小块 + 紫色主行动”语言。

### 色彩令牌

- `--paper: #fff9f2`：全站暖白背景。
- `--surface: #fffefa`：卡片和输入区域。
- `--ink: #252133`：标题和主要文字。
- `--muted: #686274`：说明文字。
- `--violet: #705be7`：主按钮、进度和选中状态。
- `--violet-soft: #eeeaff`：选中项背景。
- `--coral: #ff806f`：结果页重点和少量提醒。
- `--marker: #ffe78a`：轻量标签和特殊提示。
- `--line: #ded8e6`：卡片与输入框细边界。

所有正文与背景、按钮文字与按钮背景必须保持清晰对比；任何选中、错误和成功状态都同时使用文字或图形提示，不只依赖颜色。

### 字体与层级

继续使用中文系统字体栈，不引入远程字体资源。标题使用 800～900 字重和收紧字距；正文采用正常字距及 1.65～1.75 行高。正文行长控制在约 34rem 内。移除依赖大写、过宽字距的装饰性标签，页面小标题改用自然中文短句。

### 形状与阴影

主要卡片使用 16～20px 圆角、1px `--line` 边框和柔和短阴影。主按钮使用胶囊圆角，次按钮使用 12～14px 圆角。取消大面积 2～3px 黑边和硬偏移黑影；结果分数卡可保留更强对比，但不能让正文阅读区变暗。

## 页面设计

### 首页

首页保持单列卡片式构图，首屏直接呈现淡紫圆形锚点、小标题“看看朋友眼里的你”、主动换行的“你真的 / 懂我吗？”、玩法说明和明确主按钮。按钮下方排列三张等宽彩色信息卡，分别承载“无需注册”“25 道题”“约 3 分钟”；信息仍用于解释成本，但同时承担 B 方案的色彩节奏。已有草稿恢复卡显示在主行动附近，视觉权重低于主按钮和三色信息卡。

### 昵称与入口页

创建者昵称页和朋友昵称页使用同一套有明确边界、内层色块和短阴影的轻卡片容器，不允许内容直接漂浮在整页背景上。标签、输入框、错误信息和按钮垂直排列；输入框获得焦点时显示紫色外圈。朋友入口继续明确显示“你正在猜：某人”，草稿恢复只匹配当前分享码。

### 答题页

进度区域由题号和细进度条组成，不再使用倾斜贴纸。题卡保持单一阅读焦点，并以淡紫圆形或柔和色块建立与首页相同的视觉身份；四个选项使用圆角列表。默认选项为浅色细边，悬停时只轻微抬升；选中时显示紫色边框、淡紫背景、实心字母圆点和“已选”文字。自动前进、上一题、下一题和草稿逻辑不变。

### 创建完成页

朋友链接是唯一主操作。复制按钮成功后保留文字反馈；失败时给出可执行提示。管理链接继续放在折叠区域，并保持“不要分享”的语义层级，避免与朋友链接混淆。

### 结果页

大分数是全站唯一允许使用明显深浅对比的区域：可使用深紫背景、暖白文字和珊瑚色数字。点评紧随分数，不加入无意义装饰。错题揭晓仍为浅色卡片，创建者答案和朋友答案对齐展示。分享结果为主按钮，“我也要创建”保持次级。

### 排行榜与系统状态

排行榜沿用浅色卡片和三色节奏，每条记录形成独立小卡，明确显示“第 N 名 / 昵称 / 分数 / M月D日完成”，不再呈现意义不明的裸数字。空榜提供邀请朋友的下一步。加载、错误、草稿恢复统一使用公共状态卡；错误信息说明发生了什么和用户能做什么，不泄露内部信息。

## 响应式与动效

移动端为主，320px 宽度不得产生横向滚动；桌面端内容最大宽度约 42rem，避免把手机产品拉成宽屏仪表盘。动效只用于选项确认、进度变化和复制成功，时长控制在 120～200ms；开启 `prefers-reduced-motion` 时关闭非必要过渡。

## 实现边界

主要改动集中在 `src/app/globals.css` 和现有页面的少量语义结构。必要时可以增加无状态装饰元素或复用类名，但不新增产品功能、不更改 API 请求、不改数据库、不更改现有埋点事件。公共组件的可访问名称必须保持稳定，以避免破坏现有测试和用户习惯。

## 验收标准

1. 首页、昵称、答题、完成、结果、排行榜和系统状态采用同一令牌与圆角语言。
2. 首页在常见手机首屏内显示玩法、三枚成本标签和主行动。
3. 答题选项的默认、悬停、键盘焦点、选中、禁用状态均可区分。
4. 结果大分数有明显传播视觉，错题正文仍保持浅色高可读性。
5. 320px 宽度无横向滚动，触控目标不小于约 44px。
6. 键盘焦点清晰，减少动态偏好生效，状态不只依赖颜色。
7. 原有单元与集成测试全部通过，并补充首页信息标签和关键 UI 状态断言。
8. TypeScript、ESLint、生产构建通过；手机与桌面截图完成视觉复核。
9. 首页与原 B 方案同时具备淡紫圆形、两行标题、紫色胶囊主按钮和三张彩色信息卡；缺少任一项均不算还原完成。
10. 创建与朋友入口的主体位于可辨识的卡片容器中，桌面端主行动宽度保持紧凑，不出现横跨整个 42rem 内容区的按钮。

## 发布与回滚

实现提交推送到 GitHub `main` 后由独立 Vercel 项目自动部署。发布前保留当前 READY deployment 作为回滚点；若新版出现严重可读性、交互或运行错误，立即将生产别名切回该稳定部署。数据库无需迁移或回滚。
